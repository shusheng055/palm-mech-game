# 手相改造 · 第一版原型

React + Vite，纯浏览器本地推理，不使用云 AI API。已包含掌纹 ONNX 模型、手部定位模型、5 种透明 SVG 机械图片和基本测试。

GitHub Pages 部署地址：[手相改造原型](https://shusheng055.github.io/palm-mech-game/)。

## 运行

需要 Node.js 22.12+ 或 24+，建议使用 Chrome / Edge。解压源码包后，在 `palm-mech-game` 文件夹内打开终端：

```powershell
npm ci
npm run dev
```

打开 **http://127.0.0.1:5173/**。已安装依赖时，可直接 `npm run dev`。

首次安装依赖需要网络；模型文件已随源码提供。安装完成后，页面、模型、WASM 和图片均从本地加载，推理不需要联网。在线版本从同一个网站加载静态资源，手掌照片仍在浏览器内运行推理，不上传给服务器。不要直接双击 `index.html`。

摄像头只在点击“打开摄像头”后请求权限；需使用 localhost、127.0.0.1 或 HTTPS。点击“拍照并识别”或“关闭摄像头”会停止摄像头。拒绝权限、没有摄像头、摄像头被占用时会显示错误，可继续选择上传照片。

生成正式静态文件并预览：

```powershell
npm run build
npm run preview
```

打开 **http://127.0.0.1:4173/**。构建产物在 `dist/`，也可交给静态网站服务器托管。

## GitHub Pages 发布

仓库设置中将 Pages 的发布来源设为 GitHub Actions。每次推送到 `main` 时，`.github/workflows/pages.yml` 会安装固定版本依赖、运行核心测试、构建并部署 `dist/`。也可在 Actions 页面手动运行发布。所有第三方许可同时随静态网站发布在 `licenses/` 中。

## 玩法

1. 上传清晰手掌照片，或打开摄像头拍照。只保留一只张开的手，掌心朝向镜头，光线充足。
2. 页面自动定位、旋转、裁切手部，并用预训练 ONNX 模型识别感情线、智慧线和生命线。三条线全部通过检测才开始游戏。
3. 从随机提供的 3 件不同形状、不同大小的机械部件中选择一件。点击或拖动画布放置；也可聚焦画布后用方向键移动，回车安装。选择期间显示放置预览分数；取消预览会恢复。
4. 点击“安装并获得金额”领取游戏金钱。安装后固定；每件部件仅使用一次，本次照片最多安装 3 件。重叠覆盖的面积不会重复发钱。
5. 选择一条掌纹，以 ¥80 购买一次注射：沿一个端点延长最多 24 px，不播放动画。碰到画布边缘时缩短本次延长量，两端都无空间时不扣款。
6. 上传新照片或重新拍照，照片、掌纹、机械、注射、选择和金钱全部重新开始。

## 计分与遮挡规则

- 长度单位是归一化 **512×512 游戏画布中的 px**，不是手掌的毫米长度。表格同时显示含注射的总线长和扣除机械遮挡后的有效可见长度。
- `总分 = round(10 × 三条有效可见长度之和)`。这是游戏虚构规则，不代表健康、寿命或命运。
- 原始分割图先保留每一类中最大的连通区域，再细化为中心骨架，提取主要路径。小碎片被丢弃，不跨越断裂区域补画或拼接掌纹。
- 显示顺序固定为：**照片底层 → 掌纹及注射中层 → 机械顶层**。机械的白色填充也是不透明区域，会覆盖下层照片和曲线。
- 遮挡按 SVG 光栅化后的实际 alpha 轮廓计算，透明孔洞保留可见掌纹；alpha ≥ 128 的像素视为被替代。用不超过 0.5 px 的采样步长计算可见线长。
- 金钱为 `floor(新增覆盖像素数 × 该机械的倍率 / 100)`。每张机械图片的倍率在按钮上显示。面积指游戏画布中的图片覆盖面积，没有声称是精确的皮肤面积。
- 放置预览也遮住下层并实时影响预览分数；只有安装才发放金钱。注射延长线和原始掌纹遵循同一遮挡规则，被遮住的延长部分不加分。

## 模型与识别失败

掌纹模型来自 [samuelwbarber/palm-line-reader](https://github.com/samuelwbarber/palm-line-reader)，固定提交：

```text
bc48939f4deee6d8ff842bfde499396dab9c4830
```

随包提供 `public/models/student_fp16.onnx`，11,284,720 字节，SHA-256：

```text
e2c9f826676b3aaf0a715f3087fcd4fc0b4dccd8c53de05fd26696a8399f8dd6
```

输入严格遵守仓库元数据：RGB、512×512、NCHW、ImageNet 均值/标准差；输出为背景、感情线、智慧线、生命线的 4 类 logits。使用 ONNX Runtime Web 的 WASM 后端，在 Worker 中运行，兼容不支持 WebGPU 的浏览器。

手部定位使用本地 MediaPipe Hand Landmarker，`hand_landmarker.task` 来自同一仓库的 `pipeline/`，SHA-256：

```text
fbc2a30080c3c557093b5ddfc334698132eb341044ccee322ccf8bcf3607cde1
```

定位后将手指方向转向上方，按手部包围框加 15% 边距裁切，并按上游约定统一左右方向。

每条线需满足：预测像素类别正确且 softmax 概率 ≥ 0.55，主要连通区域至少 60 像素，骨架路径长度至少 45 px，路径平均概率 ≥ 0.60。这些阈值是原型的启发式检查，不是经过标定的识别准确率保证。缺任一线时显示具体缺失线名，整次结果不计分、不提供机械、不允许注射。

未检测到手、检测到多只手、图片无法读取、模型缺失或不完整、本地运行文件加载失败、推理超时，均会明确报错。没有备用假线、预设掌纹或假成功模式。模型获取失败后可恢复文件再上传重试。

**已观察到的模型限制：**上游 `examples/example_input.png` 在本次真实模型测试中输出全背景，页面正确拒绝；`docs/example1_input.png` 至 `example4_input.png` 在直接输入模型测试中均输出三类掌纹。完整页面通过了第一张清晰图片的识别测试。这不保证任意用户照片都成功；拒绝时应换清晰照片，不能以测试通过替代实际照片验收。

如模型文件损坏，可从上述固定提交的 `models/` 恢复；不要把 Git LFS 指针或 GitHub 网页保存成 `.onnx`。运行说明不会让程序在缺模型时伪装识别。

## 测试

```powershell
npm test
npm run build
npm run smoke
```

`npm run smoke` 启动 4173 端口的正式构建预览，默认调用已安装的 Chrome。若仅安装 Edge，可先设置：

```powershell
$env:PALM_TEST_BROWSER = 'msedge'
npm run smoke
```

测试使用真实本地 ONNX 文件；摄像头测试使用录制的掌心静态视频，权限拒绝测试使用显式模拟错误。测试代码不会进入正式页面。详情见 [测试结果](SMOKE_TEST.md)。

## 源码

- `src/App.jsx`：上传、摄像头、三层画布、机械操作、注射、状态重置。
- `src/vision.js`：本地手部定位和照片预处理。
- `src/inference.worker.js`：本地 ONNX 加载、归一化、推理与输出检查。
- `src/trace.js`：置信度过滤、连通区域、骨架、主要路径及缺线错误。
- `src/game.js`：长度、遮挡、计分、金钱和注射规则。
- `src/parts.js`、`public/parts/`：透明机械 SVG、随机尺寸和实际 alpha 遮罩。
- `scripts/copy-runtime.mjs`：安装依赖后复制运行文件到本地 `public/runtime/`。
- `tests/`：核心规则测试与浏览器 smoke test。

没有账户、存档、云服务、商业支付或额外玩法。
